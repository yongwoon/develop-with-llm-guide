여러 file 과 여러 commit 에 걸치는 기능은 spec 을 먼저 다듬고 task 로 나눈 뒤, 실행 방식 하나를 골라 구현합니다.

<Aside title="언제 쓰나">
- 기능 하나가 여러 화면·module 에 걸쳐 PR 하나로 끝나지 않을 때
- 구현 전에 spec 을 검토 통과 상태로 만들고 싶을 때
</Aside>

### 5. 실행 방식 하나 고르기

task 가 순서대로 이어지면 <SkillLink name="ywc-sequential-executor" />, 서로 독립인 task 가 많으면 <SkillLink name="ywc-parallel-executor" />, task 분해 없이 spec 에서 바로 code 를 만들려면 <SkillLink name="ywc-code-gen" /> 을 씁니다.

<Tabs syncKey="tool">
<TabItem label="Claude Code">
```text
/ywc-task-executor 000003-010..000003-050 --local-merge --review
/ywc-sequential-executor 000003-010..000003-050 --local-merge --review
/ywc-parallel-executor 000004-010..000004-030 --aggregate-pr --review
/ywc-code-gen --spec docs/ywc-plans/<plan-file>.md --tdd --review
```
</TabItem>
<TabItem label="Codex">
```text
$ywc-task-executor 000003-010..000003-050 --delivery local-merge --review
$ywc-sequential-executor 000003-010..000003-050 --local-merge --review
$ywc-parallel-executor 000004-010..000004-030 --aggregate-pr --review
```

## 건너뛸 수 있는 조건

- **6단계 <SkillLink name="ywc-impl-review" />**: 5단계 executor 를 `--review` 와 함께 실행했다면 task 마다 리뷰가 이미 끝나 있습니다. 이 단계는 전체 변경을 한 번 더 볼 때만 실행합니다.
- **7단계 <SkillLink name="ywc-security-audit" />**: 인증, 외부 입력, 민감 data 를 건드리지 않는 변경이면 건너뜁니다.
- **8단계 <SkillLink name="ywc-finish-branch" />**: 5단계에서 executor 를 썼다면 task 마다 병합과 완료 처리까지 끝나므로 건너뜁니다. <SkillLink name="ywc-code-gen" /> 으로 만든 branch 는 이 단계로 마무리합니다.
- 변경이 file 몇 개로 끝나면 [12 작은 변경](/develop-with-llm-guide/flows/small-change/) 흐름을 씁니다.
