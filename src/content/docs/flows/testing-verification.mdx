테스트와 검증에 쓰는 skill 은 서로 독립입니다. 지금 필요한 확인 방법을 하나 이상 골라 씁니다.

<Aside title="언제 쓰나">
- 구현을 test 로 뒷받침하거나 QA 용 수동 테스트시트가 필요할 때
- "끝났다"고 말하기 전에 실제 명령 결과로 확인하고 싶을 때
</Aside>

## 건너뛸 수 있는 조건

- 다섯 단계는 서로 독립인 선택 단계입니다. 변경에 맞는 것만 씁니다.
- 동작을 바꾸는 code 변경이라면 <SkillLink name="ywc-tdd-ritual" /> 과 <SkillLink name="ywc-verify-done" /> 은 건너뛰지 않는 편이 좋습니다.
- E2E 환경과 검증 계약은 한 번 만들어 두면 다음부터는 `--audit` 이나 `--flow` 로 갱신만 합니다.
