ywc skill 은 `/ywc-commit` 처럼 이름으로 부르지 않아도 시작할 수 있습니다. "바꾼 거 커밋해줘" 라고 쓰면 <SkillLink name="ywc-commit" /> 이 시작됩니다.

## 왜 말로도 시작되나

skill 마다 언제 쓰는 skill 인지 적은 설명이 있습니다. 도구는 요청 문장을 이 설명과 맞춰 보고, 맞는 skill 이 있으면 그 skill 을 씁니다. ywc skill 의 설명에는 한국어, 영어, 일본어 표현이 함께 들어 있어서 세 언어 중 어느 것으로 요청해도 됩니다.

| 도구 | 이름으로 부르기 | 말로 부르기 |
|---|---|---|
| Claude Code | `/ywc-…` | 요청이 skill 설명과 맞으면 도구가 그 skill 을 불러 씁니다. |
| Codex | `$ywc-…` | 요청이 skill 설명과 맞으면 도구가 그 skill 을 골라 씁니다. |

## 말로 부르는 예

아래는 말로 요청했을 때 시작되는 skill 의 예입니다. 문장이 꼭 같을 필요는 없습니다.

| 이렇게 말하면 | 시작되는 skill |
|---|---|
| 오늘 바꾼 거 커밋하고 push 까지 해줘 | <SkillLink name="ywc-commit" /> |
| Open a pull request for this branch | <SkillLink name="ywc-create-pr" /> |
| 이 PR 에 달린 리뷰 코멘트 정리해서 반영해줘 | <SkillLink name="ywc-handle-pr-reviews" /> |
| この仕様書をレビューしてください | <SkillLink name="ywc-spec-validate" /> |
| 정적 사이트용으로 Astro 와 VitePress 를 비교해줘 | <SkillLink name="ywc-tech-research" /> |
| 아직 안 끝난 task 들 돌려줘 | <SkillLink name="ywc-task-executor" /> |
| rebase 중에 충돌이 났어. 같이 풀어줘 | <SkillLink name="ywc-resolve-conflict" /> (Claude Code 전용) |

## 이름으로 부르는 편이 나은 때

다음 경우에는 `/ywc-…` 나 `$ywc-…` 로 skill 을 직접 고릅니다.

- **option 이 필요할 때**: `--local-merge`, `--mode llm` 처럼 동작을 정확히 정해야 할 때입니다.
- **비슷한 skill 이 여럿일 때**: 예를 들어 리뷰 계열이나 실행기 계열은 요청 문장만으로는 어느 쪽인지 갈릴 수 있습니다. 비교는 [헷갈리기 쉬운 skill](/develop-with-llm-guide/guides/choosing-skills/) 을 봅니다.
- **특정 skill 을 쓰고 싶을 때**: "task 실행해줘" 는 <SkillLink name="ywc-task-executor" /> 가 순차·병렬을 정합니다. 순서대로 돌리고 싶다면 <SkillLink name="ywc-sequential-executor" /> 를 이름으로 부릅니다.
- **직접 호출 전용 skill 일 때**: <SkillLink name="ywc-setup" />, <SkillLink name="ywc-handoff" />, <SkillLink name="ywc-retro" />, <SkillLink name="ywc-merge-dependabot" /> 은 이름으로 불러야 합니다.

<Aside title="직접 호출 전용 skill">
Claude Code 에서는 위 네 skill 이 말로 요청해서는 시작되지 않습니다. Codex 에서는 직접 호출을 권고하는 설정이라, 말로 요청해도 선택될 수 있습니다. 두 도구 모두 이름으로 부르면 확실합니다.
</Aside>

## 말로 요청하면서 option 주기

말로 요청할 때도 option 을 줄 수 있습니다. 방법은 두 가지입니다.

1. **명령 형태를 문장에 넣습니다.** 이름과 option 을 그대로 쓰고 뒤에 설명을 붙입니다. 이 방법이 가장 확실합니다.

   ```text
   /ywc-task-executor 000001-010..000001-040 --local-merge --review
   ```

   Codex 에서는 `/` 대신 `$` 를 씁니다. Codex 의 <SkillLink name="ywc-task-executor" /> 는 `--local-merge` 대신 `--delivery local-merge` 를 받습니다.

2. **option 을 말로 적습니다.** "PR 없이 직접 병합하고, task 마다 리뷰도 해줘" 처럼 씁니다. 도구가 알맞은 option 을 고르기를 기대하는 방법이라 정확하지 않을 수 있습니다. 실행 전에 보여 주는 계획이나 확인 질문에서 값을 확인합니다.

<SkillLink name="ywc-commit" /> 처럼 option 이 없는 skill 은 원하는 동작을 문장에 적습니다. push 까지 원하면 "push 까지" 라고 씁니다.
