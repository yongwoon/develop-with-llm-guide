ywc skill 은 언어와 task 크기를 정하지 않으면 실행할 때마다 묻고, base branch 는 저장소에서 추정합니다. 이 값을 설정 file 에 한 번 저장해 두면 더 묻지 않습니다. 저장은 보통 <SkillLink name="ywc-setup" /> 으로 합니다.

## 설정 file 위치

| 범위 | Claude Code | Codex | 쓰임 |
|---|---|---|---|
| project | 저장소 root 의 `.ywc-config.json` | 저장소의 `.codex/ywc.json` | 저장소에 commit 해 공동 작업자와 공유합니다. `.gitignore` 에 넣지 않습니다. |
| 사용자 | `~/.claude/ywc-config.json` | `~/.codex/ywc.json` (`CODEX_HOME` 이 있으면 그 아래 `ywc.json`) | 내 모든 project 에 적용합니다. |

git 저장소 밖에서 project 범위로 저장하면 현재 디렉터리에 file 을 만들고, 그 사실을 한 줄로 알려 줍니다.

## 설정할 수 있는 key

설정 file 은 JSON object 하나입니다. `lang.doc` 같은 이름은 점이 들어간 key 그대로 씁니다. `{"lang": {"doc": "ko"}}` 처럼 중첩하면 읽지 않습니다.

| key | 값 | ywc-setup option | 쓰는 skill |
|---|---|---|---|
| `lang` | `ko`, `ja`, `en`, `zh`, `es` | `--lang` | 언어를 정하는 모든 skill 의 기본 언어 |
| `lang.doc` | 같은 코드 | `--lang-doc` | 문서를 만드는 skill: <SkillLink name="ywc-spec-writer" />, <SkillLink name="ywc-project-docs" />, <SkillLink name="ywc-spec-ready" />, <SkillLink name="ywc-auth-implement" />, <SkillLink name="ywc-incident-postmortem" />, <SkillLink name="ywc-gen-testcase" /> |
| `lang.task` | 같은 코드 | `--lang-task` | <SkillLink name="ywc-task-generator" /> 의 task 문서 |
| `lang.pr` | 같은 코드 | `--lang-pr` | <SkillLink name="ywc-create-pr" /> 의 PR 제목과 설명 |
| `initials` | 소문자·숫자 2~4자 | `--initials` | <SkillLink name="ywc-task-generator" /> 가 task 번호에 붙이는 이니셜 |
| `granularity` | `human`, `llm` | `--granularity` | <SkillLink name="ywc-task-generator" /> 의 기본 task 크기 (`--mode` 의 기본값) |
| `baseBranch` | branch 이름 | `--base-branch` | PR 과 병합의 대상 branch. <SkillLink name="ywc-create-pr" />, <SkillLink name="ywc-finish-branch" />, <SkillLink name="ywc-agentic" />, Codex 의 executor 가 씁니다. Claude Code 의 executor 는 이 값을 쓰지 않고, `--base-branch` 가 없으면 각 skill page 의 기본값(예: develop → main → master 순, 또는 현재 branch)을 따릅니다 |

### 언어 코드와 별칭

입력할 때는 별칭도 받지만 file 에는 아래 다섯 코드만 저장됩니다. 직접 file 을 고칠 때도 이 코드로 적습니다.

| 코드 | 언어 | 받는 별칭 |
|---|---|---|
| `ko` | 한국어 | `kr`, `korean`, `한국어` |
| `ja` | 일본어 | `jp`, `japanese`, `日本語` |
| `en` | 영어 | `english`, `eng` |
| `zh` | 중국어 | `chinese`, `中文`, `zh-cn`, `zh-tw` |
| `es` | 스페인어 | `spanish`, `español`, `espanol` |

`zh-cn` 과 `zh-tw` 는 모두 `zh` 로 저장됩니다. 번체·간체 구분이 필요하면 실행할 때 따로 요청합니다.

## 어떤 값이 적용되는지

같은 값이 여러 곳에 있으면 위쪽이 이깁니다.

| 순위 | 언어 (`lang`, `lang.*`) | task 크기 (`granularity`) | base branch (`baseBranch`) |
|---|---|---|---|
| 1 | 실행할 때 준 option (`--lang`, executor 의 `--pr-lang` 등) | `--mode` | `--base-branch` |
| 2 | project 설정 file | project 설정 file | project 설정 file |
| 3 | 저장소의 `AGENTS.md`·`CLAUDE.md` 에 적힌 언어 정책 | — | — |
| 4 | 사용자 설정 file | 사용자 설정 file | 사용자 설정 file |
| 5 | 물어봄 | 물어봄 | 저장소의 branch 로 추정 (`develop`, `main`, `master` 순) |

- `lang.doc`·`lang.task`·`lang.pr` 은 **같은 file 안에서만** `lang` 보다 우선합니다. project file 에 `lang` 만 있고 사용자 file 에 `lang.pr` 이 있으면, project 의 `lang` 이 적용됩니다.
- 값이 잘못되었거나 file 이 깨져 있으면 그 값은 쓰지 않고 다음 순위의 값을 씁니다. skill 이 멈추지는 않습니다.
- <SkillLink name="ywc-gen-testcase" /> 는 마지막에 묻지 않고 스스로 언어를 정합니다.

## 예: 이 저장소는 한국어, PR 만 일본어

문서와 task 는 한국어로, PR 은 일본어 사용자가 읽도록 일본어로 쓰는 저장소입니다.

<Tabs syncKey="tool">
<TabItem label="Claude Code">
```text
/ywc-setup --scope project --lang ko --lang-pr ja
```
</TabItem>
<TabItem label="Codex">
```text
$ywc-setup --scope project --lang ko --lang-pr ja
```
</TabItem>
</Tabs>

저장된 file (`.ywc-config.json` 또는 `.codex/ywc.json`) 입니다.

```json
{
  "lang": "ko",
  "lang.pr": "ja"
}
```

이후 <SkillLink name="ywc-spec-writer" /> 와 <SkillLink name="ywc-task-generator" /> 는 한국어로, <SkillLink name="ywc-create-pr" /> 는 일본어로 씁니다. 이번 PR 만 영어로 쓰려면 `--lang en` 을 붙여 실행합니다.

## ywc-setup 과 직접 편집

| 상황 | 방법 |
|---|---|
| 처음 설정하거나 값을 바꿀 때 | <SkillLink name="ywc-setup" />. 값을 검사하고, 별칭을 코드로 바꾸고, file 의 다른 key 는 그대로 둡니다. 저장한 경로와 JSON 을 보여 줍니다. |
| 무엇을 설정할지 고르고 싶을 때 | Claude Code 에서는 `--scope` 만 주고 실행합니다. 설정할 항목을 고르게 한 뒤 고른 것만 묻습니다. `--scope` 도 없으면 저장 범위부터 묻습니다. Codex 에서는 `--scope` 외에 저장할 값을 하나 이상 함께 줍니다. |
| key 를 지우거나 여러 값을 한 번에 정리할 때 | file 을 직접 고칩니다. 위 표의 key 이름과 코드를 그대로 씁니다. |
| ywc-setup 이 다루지 않는 key (아래 Codex 의 `subagentModelPolicy`) | file 을 직접 고칩니다. |
| 이번 한 번만 다른 값을 쓸 때 | 설정을 바꾸지 않고 각 skill 의 option 을 씁니다. |

## 외부 URL 정책 (Spec Reference)

<SkillLink name="ywc-task-generator" /> 가 만든 task 의 Spec Reference 에는 Notion, Confluence, Figma 같은 외부 URL 이 들어갈 수 있습니다. <SkillLink name="ywc-sequential-executor" /> 는 이 URL 을 읽을지 project 마다 한 번 묻고, 답을 local 설정 file 에 저장합니다. 그 뒤로는 묻지 않습니다.

| 값 | 동작 |
|---|---|
| `deny` (기본) | 외부 URL 을 읽지 않습니다. 건너뛴 URL 은 기록만 남습니다. |
| `allow` | task 에 적힌 외부 URL 을 모두 읽습니다. |
| `allowlist` | 목록에 있는 host·경로로 시작하는 URL 만 읽습니다. |

| | Claude Code | Codex |
|---|---|---|
| 저장 file | `.claude/settings.local.json` | `.codex/settings.local.json` |
| 정책 key | `taskExecutor` 아래 `externalSpecUrls` | `ywDevSequentialExecutor` 아래 `externalSpecUrls` |
| 허용 목록 key | 같은 곳의 `externalSpecUrlAllowlist` | 같은 곳의 `externalSpecUrlAllowlist` |
| `--non-interactive` 로 실행했는데 정한 값이 없을 때 | 묻지 않고 이번 실행만 `deny` 로 처리합니다. 저장하지 않습니다. | 실행하지 않고 멈춥니다. 먼저 대화형으로 실행해 정합니다. |

Claude Code 의 예입니다. file 의 다른 key 는 그대로 둡니다.

```json
{
  "taskExecutor": {
    "externalSpecUrls": "allowlist",
    "externalSpecUrlAllowlist": ["github.com", "figma.com/file"]
  }
}
```

답을 바꾸려면 이 key 를 고치거나 지웁니다. 지우면 다음 실행에서 다시 묻습니다.

## Codex 에서 다른 점

- 사용자 설정 file 은 `CODEX_HOME` 을 따릅니다. 없으면 `~/.codex/ywc.json` 입니다.
- 기존 설정 file 이 깨진 JSON 이면 <SkillLink name="ywc-setup" /> 은 덮어쓰지 않고 멈춥니다. file 을 고친 뒤 다시 실행합니다.
- 잘못된 설정값을 건너뛰면 경고를 한 줄 보여 줍니다. 결과에 적용된 값이 어느 file 에서 왔는지 함께 적는 skill 도 있습니다.
- 언어 정책은 `AGENTS.md`·`CLAUDE.md` 외에 `CODEX.md` 도 참고합니다.
- `granularity` 는 대화형 실행에서만 쓰입니다. 질문 없이 실행할 때는 `--mode` 를 직접 줘야 합니다.
- 설정한 `baseBranch` 가 저장소에 없으면 다른 branch 로 추정하지 않고 멈춥니다.
- `subagentModelPolicy` key 를 더 쓸 수 있습니다. 값은 `balanced`, `economy`, `quality`, `inherit` 이고, executor 의 `--model-policy` 를 주지 않았을 때의 기본값이 됩니다. 정하지 않으면 `balanced` 입니다. <SkillLink name="ywc-setup" /> 으로는 저장할 수 없어 file 을 직접 고칩니다.

<Aside type="tip" title="잘 적용되지 않을 때">
값이 적용되지 않으면 [문제 해결](/develop-with-llm-guide/guides/troubleshooting/) 을 봅니다.
</Aside>
