## 사용 case

### 작은 변경을 바로 실행 계획으로

footer 에 저장소 link 를 하나 추가하는 정도의 작은 변경입니다.

<Tabs syncKey="tool">
<TabItem label="Claude Code">
```text
/ywc-plan 사이트 footer 에 GitHub 저장소 link 를 추가하고 싶다
```
</TabItem>
<TabItem label="Codex">
```text
$ywc-plan 사이트 footer 에 GitHub 저장소 link 를 추가하고 싶다
```
</TabItem>
</Tabs>

**결과물**: 작은 변경으로 판단하면 실행 계획을 씁니다. 계획은 `docs/ywc-plans/YYYYMMDD-small_<slug>.md` 에 생깁니다.

### 여러 module 에 걸친 기능

skill page 마다 option 표를 자동으로 그리는 기능입니다. 변경 범위가 큽니다.

<Tabs syncKey="tool">
<TabItem label="Claude Code">
```text
/ywc-plan skill page frontmatter 에서 option 표와 색인을 자동 생성하고 싶다
```
</TabItem>
<TabItem label="Codex">
```text
$ywc-plan skill page frontmatter 에서 option 표와 색인을 자동 생성하고 싶다
```
</TabItem>
</Tabs>

**결과물**: 중·대형으로 판단하면 spec 문서를 씁니다. 문서는 `docs/ywc-plans/YYYYMMDD-<slug>.md` 에 생깁니다. 이어서 `ywc-spec-ready` 로 다듬고 `ywc-task-generator` 로 넘기라는 안내가 나옵니다.

## 쓰지 말아야 할 때

- 무엇을 만들지 아직 흐릴 때 → `ywc-brainstorm`
- 이미 있는 spec 을 점검할 때 → `ywc-spec-validate`
- 완성된 spec 을 task 로 나눌 때 → `ywc-task-generator`
- project 전체 사양서를 쓸 때 → `ywc-spec-writer`
- 초안 spec 을 통과 상태까지 다듬을 때 → `ywc-spec-ready`
- 여러 세션에 걸친 불확실한 큰 작업일 때 → `ywc-wayfinder`
