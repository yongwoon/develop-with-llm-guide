## 사용 case

### branch 의 작업을 spec 과 대조

option 표 기능을 다 만들었습니다. PR 전에 spec 과 맞는지 확인합니다.

<Tabs syncKey="tool">
<TabItem label="Claude Code">
```text
/ywc-impl-review --spec docs/ywc-plans/20261028-option-table.md --git-range main..HEAD
```
</TabItem>
<TabItem label="Codex">
```text
$ywc-impl-review --spec docs/ywc-plans/20261028-option-table.md --git-range main..HEAD
```
</TabItem>
</Tabs>

**결과물**: 여러 관점의 지적이 심각도와 함께 나옵니다. spec 의 요구사항마다 구현 여부를 표시한 대응표와 수정 우선순위도 나옵니다.

### commit 전 변경만 빠르게

<Tabs syncKey="tool">
<TabItem label="Claude Code">
```text
/ywc-impl-review --working-tree
```
</TabItem>
<TabItem label="Codex">
```text
$ywc-impl-review --spec docs/ywc-plans/20261028-option-table.md --code src/components/
```
</TabItem>
</Tabs>

**결과물**: Claude Code 는 commit 하지 않은 변경을 spec 없이 리뷰합니다. Codex 에는 이 option 이 없어 code 경로와 spec 으로 리뷰합니다.

## 쓰지 말아야 할 때

- spec 문서만 검토할 때 → `ywc-spec-validate`
- 보안만 집중해서 볼 때 → `ywc-security-audit`
- 받은 리뷰 지적에 대응할 때 → `ywc-receive-review`
- 열린 PR 의 리뷰 코멘트를 처리할 때 → `ywc-handle-pr-reviews`
- 작업이 정말 끝났는지 확인할 때 → `ywc-verify-done`
